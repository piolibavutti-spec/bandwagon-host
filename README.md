# 搬瓦工 VPS 入门：从选择用途到连接服务器

搬瓦工（BandwagonHost）提供基于 KVM 虚拟化的 VPS。可以把 VPS 理解为一台通过网络管理的服务器：购买后，你得到的是系统资源和远程管理入口，而不是一台已经装好各种图形应用的个人电脑。安装软件、维护系统和保存数据，通常需要自己处理。

如果你想练习 Linux、搭建个人网站，或尝试部署 Dify 这样的应用，这类服务器可以成为实践环境。对新手来说，关键不是先买最大的配置，而是先想清楚运行什么、谁会访问，以及自己是否愿意学习基本的命令行和维护操作。KiwiVM 控制面板负责服务器的基础管理；进入系统后的软件配置则需要通过 SSH 或其他管理工具完成。

## 先确定用途，再比较套餐

选择时可以按下面的顺序考虑：

1. **确定任务**：只练习命令行，还是要同时运行网站、数据库和应用？后者需要为多个进程和数据存储留出空间。
2. **估计资源**：内存关系到同时运行的程序，CPU 核数影响可用计算资源，磁盘需要容纳系统、软件和数据；月流量则关系到网络传输的使用量。
3. **考虑访问者和机房**：常规 KVM 提供欧美机房选项；CN2 GIA-E 提供包含 CN2 GIA 等线路的机房选择。日本大阪和香港有各自的套餐，适合希望比较亚洲机房的读者。
4. **比较付款周期**：按实际预算对照月付、季付、半年付或年付价格，不要只比较单次付款金额，也要留意续费安排。

以下搬瓦工套餐对比中的配置和价格依据参考资料整理，美元价格及可选周期可能变化，购买前以各产品页面显示的信息为准。表内带宽是套餐标称值，并不代表实际下载速度或特定地区的访问延迟。

## 购买后：第一次连接服务器

### 在 KiwiVM 中找到连接信息

登录账户后台，在 **Services → My Services** 中找到购买的 VPS，点击 **KiwiVM Control Panel**。首页的 **Public IP address** 是服务器公网 IP，**SSH Port** 是连接所需端口；记录这两项，不要假定端口一定是 22。

服务器处于开机状态时，在左侧选择 **Root password modification**，点击生成并设置新 root 密码。按面板提示查看注册邮箱获取密码。root 是系统管理员账户，应妥善保存密码，不要将它贴在公开文档或聊天记录中。

### 用 SSH 登录

Windows 用户可打开 PowerShell，macOS 或 Linux 用户可打开终端。下面的示例使用文档专用 IP 和示例端口；执行时将它们替换成 KiwiVM 显示的实际值：

```bash
ssh root@192.0.2.10 -p 12345
```

命令中的 `root` 是登录用户名，`-p` 后面是 SSH 端口。按提示完成认证后，终端会进入服务器的命令行环境。首次使用时，仔细核对连接对象和显示的提示；后续操作是在远程服务器上执行，而不是在本机执行。

如果远程连接失败，先回到面板确认服务器是否开机，再检查 IP、端口和密码是否抄错。也可以使用 KiwiVM 中的 **Check if my IP is banned** 工具辅助判断 IP 的可访问情况。检查结果只是排查线索；不要在尚未确认原因时就重装系统或更换机房。

## 用服务器练习 Linux

服务器系统可以选择 Ubuntu、Debian 等发行版。需要重新安装时，在 KiwiVM 进入 **Install new OS**，查看当前可选系统并按页面提示确认。重装会影响现有系统和数据，操作前先备份需要保留的文件、数据库和配置，并确认备份可用；不要把重装当成无代价的故障排查步骤。

连接成功后，可以先用下面的命令认识系统资源。它们分别查看内核信息、磁盘空间、内存以及运行中的进程；查看结果有助于理解应用安装后资源发生了什么变化。

```bash
uname -a
df -h
free -h
top
```

`top` 会持续显示进程状态，按 `q` 退出。学习时可以先观察空闲系统，再启动自己的程序进行对照。系统有问题时，磁盘是否已满、内存使用情况和进程状态也都是有用的初步线索。

在 Debian 或 Ubuntu 上，下面的命令更新软件包列表并升级已安装的软件包。执行升级会改动系统，先了解提示内容，并在有重要服务时做好备份：

```bash
sudo apt update && sudo apt upgrade
```

如果已经以 root 登录，也可以不写 `sudo`。KiwiVM 中的 **Root shell – basic** 是浏览器端的命令行入口，可以作为面板内的操作方式；无论从哪里进入，管理员命令都应在确认作用后再执行。

## 建立个人网站：从环境到 WordPress

一个网站通常由几部分组成：域名或服务器 IP 供访问者找到站点；Web 服务接收请求；数据库保存应用数据；WordPress 等程序负责内容管理。管理面板可以把部分安装和配置工作放到图形界面中，但不会替代对账户、数据和更新的管理。

以宝塔面板和 LNMP 为例，可按以下顺序准备：

1. 先连接服务器，确认系统版本适用于面板安装方式，并为网站文件和数据库预留空间。
2. 查看[宝塔 Ubuntu/Debian 安装脚本](https://download.bt.cn/install/install-ubuntu_6.0.sh)的来源及当前安装说明。参考资料提供的安装方式如下；远程脚本会以管理员权限执行，运行前应自行核验脚本内容、来源和系统适用性。

   ```bash
   wget -O install.sh https://download.bt.cn/install/install-ubuntu_6.0.sh
   bash install.sh ed8484bec
   ```

3. 安装完成后，记录输出的面板地址、用户名和密码，通过浏览器进入面板。不要公开这些登录信息。
4. 在面板中安装 LNMP 环境：Linux 系统上运行 Nginx、MySQL 和 PHP。然后在“网站”中添加站点，填写准备使用的域名或 IP，并创建数据库。
5. 上传 WordPress 安装包，或使用面板提供的安装功能；按照安装界面填写数据库信息并完成站点初始化。使用域名时，还需将域名指向服务器，并核对站点配置。

建站配置要随内容、访问量及同时运行的服务调整。[CN2 GIA-E 1GB 产品页面](https://bwh81.net/aff.php?aff=85082&pid=87)可作为入门比较对象，但不能据此断定它适合所有网站。上线后应分别保存网站文件和数据库备份，并定期检查能否恢复。

## 部署 Dify：先准备资源和配置

Dify 是用于构建 AI 应用的平台，可以接入模型并用于搭建聊天或知识库问答等应用。自托管涉及容器、配置文件和外部模型服务：服务器承载应用并不意味着所有请求都不会经过第三方，具体数据流取决于选择的模型和服务。

开始前，查看 [Dify 代码仓库](https://github.com/langgenius/dify.git)中当前的部署文档和资源要求，确认系统、内存、磁盘及 Docker Compose 的要求。参考资料列出的 [CN2 GIA-E 2GB 方案](https://bwh81.net/aff.php?aff=85082&pid=88)可作为选型对象；是否足够取决于实际版本和工作负载。

以 Docker 部署为例，基本流程是：

1. 安装 Docker 和 Compose，确认服务正常运行。参考资料使用 [Docker 安装脚本](https://get.docker.com)；执行远程脚本前应阅读并核验其来源、内容和适用性。
2. 获取 Dify 仓库，进入其 `docker` 目录。参考资料使用 `git clone https://github.com/langgenius/dify.git` 获取代码。
3. 按当前文档将示例环境文件复制为 `.env`，检查需要修改的配置，再通过 Docker Compose 启动服务。配置文件可能包含敏感信息，应限制访问并妥善保管。
4. 根据项目文档访问初始化页面，创建管理账户。在模型设置中选择提供商并填入相应 API Key，再测试应用所需的模型连接。
5. 检查服务状态、磁盘空间与日志，并为配置及业务数据制定备份方案。模型 API 的费用、权限和数据处理方式应以所选提供商的条款为准。

版本升级可能改变配置和启动步骤，因此不要把一次安装时的命令当作永久不变的操作手册。升级前同样应检查更新说明并备份数据。

## 日常管理与操作前检查

KiwiVM 的 **Main controls** 提供开机、关机和重启操作。服务器无响应时，可以先确认面板中的电源状态；重启可能中断正在运行的网站和任务，操作前应考虑影响。

**Snapshots** 可用于手动保存快照，**Automatic Backups** 提供自动备份功能。快照或自动备份能帮助恢复，但重要文件和数据库仍应有明确的备份与恢复计划，并检查备份覆盖了哪些内容。系统重装、应用升级和迁移之前，尤其需要确认可恢复的数据副本。

面板的 **SSH Keys** 功能可管理公钥，配合密钥登录减少对密码登录的依赖。私钥应留在受保护的设备上，不要上传或分享；更改登录方式前，先确认自己仍有可用的管理入口。

需要迁移机房时，可查看 **Migration** 中的选项和提示。迁移前备份数据，核对套餐可用的目标机房及操作条件，并留意公网 IP 是否变化；如果站点使用域名或其他服务依赖旧 IP，还需要相应检查和更新配置。不要假设所有迁移都免费、瞬时完成或不会影响业务。
